# 应用内复制和粘贴没有刷新最近使用排序

- 发现日期：2026-10-23；需求来自 2026-10-22 的反馈。
- 影响范围：0.3.1 及此前同一选择／粘贴路径；不影响完整内容指纹去重。
- 严重程度：P2，影响高频历史复用；未发现本问题导致数据丢失。
- 修复状态：未发布开发改动；修复 commit 可通过 `git log --all --grep='支持容量设置并按最近使用整理历史'` 定位。

## 现象与复现

选中较旧的条目，点击复制或粘贴后重新打开面板，条目仍停留在原位置。重复可见文字是否应合并是另一个问题：用户已确认保留实际格式差异，不按预览文字强行去重。

使用命名剪贴板、临时数据库和现有隔离 UI 宿主，调用面板实际绑定的选择回调，分别验证复制与粘贴路径。修复前执行 `bash scripts/check-ui.sh`：

```text
copyDoesNotDuplicateHistory = true
pasteDoesNotDuplicateHistory = true
copyMovesExistingItemFirst = false
pasteMovesExistingItemFirst = false
```

该复现不操作真实终端，不读取系统剪贴板。粘贴动作在演示模式降级为命名剪贴板复制，不能作为第三方应用真实插入的验收证据。

## 定位与根因

检查三个方向：剪贴板格式差异造成的多个指纹、选择路径没有更新存储、面板异步刷新使用旧排序。

复现中条目 ID 集合不变，排除了这条链路中的新增重复项。`ClipboardMonitor.skipCurrentChange()` 会跳过应用自己的剪贴板写入，这是避免循环采集所必需的；但选择路径没有显式记录使用时间。查询只按 `copied_at` 排序，所以应用内复制和粘贴都不会改变排名。只刷新面板不能修复存储排序依据缺失。

## 修复内容

1. 保持原完整内容指纹；格式不同仍独立，同内容重采集保留名称与收藏。
2. 新增活动附表与兼容旧写入的触发器，不改变主表 11 列或 schema 版本。旧数据以复制时间回填。
3. 成功写入剪贴板后显式记录使用，发送粘贴指令后再次记录；失败的写入不前移。已经成功复制但随后无法自动粘贴时，仍按成功复制计入使用。
4. 查询、卡片时间、时间筛选、条数／容量／过期清理统一使用最近使用时间，保留独立的最近采集时间。
5. 提供 64 MiB 至 2 GiB 的容量预设、用量显示与降容确认；收藏占用计入预算但不自动删除，失败事务回滚，成功后才保存新设置。
6. 备份携带可选活动时间，旧备份兼容且不倒退已有活动；保留独立 384 MiB 备份安全上限，超大文件在完整读取前拒绝。

## 验证方法与边界

- 最终结果：56 个场景、275 个断言通过，连续复跑三次零失败；实际 Release 包普通／全屏各 60 项检查和设置四项检查通过。完整记录见 `../verification.md`。
- `bash scripts/check.sh`：存储／格式差异去重／最近使用／筛选／迁移／备份／清理／回滚与偏好持久化，以及 Release 编译。
- `CLIPDUNE_UI_CONFIGURATION=release bash scripts/check-ui.sh bundle`：实际开发包的普通／全屏交互、最近使用前移、ID 集合与采集时间不变、设置页面和降容确认／取消。
- 精确时间断言使用固定整秒夹具。直接用实时 `Date()` 做 SQLite 秒数往返的严格相等断言，可能产生约 0.12 微秒的表示误差；这不是排序逻辑错误。
- 不验证真实终端插入、手动 `⌘V` 监听、正式升级重启、签名公证或发布。

## 避免再犯

自身写入抑制与最近使用记录必须成对设计；不能期待监听器补记被主动跳过的事件。验收同时检查顺序、条目身份、原始格式、名称／收藏和时间语义。扩大容量不能静默取消单项和备份的安全限制；设置持久化必须晚于数据库事务成功。
