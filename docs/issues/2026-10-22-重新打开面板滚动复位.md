# 重新打开面板没有回到最新项

- 发现日期：2026-10-22。
- 影响版本：0.3.0 及此前同一面板定位逻辑。
- 严重程度：P2，影响高频历史查找，未发现数据丢失。
- 修复版本：0.3.1；修复 commit 可通过 `git log --all --grep='修复面板重开滚动复位并增加回到最新按钮'` 定位。

## 现象与复现

横向滚到旧记录后关闭面板，再次打开仍然停留在旧滚动位置。即使第一项被标记选中，第一张卡片也可能只露出一部分。

使用独立测试宿主、临时数据库和 48 条额外合成历史构造必定可横向滚动的内容。将选中项放到第 21 项，滚动到中部偏移后关闭再打开，同时观测打开返回时和异步数据返回后的 NSClipView 横向坐标。

```text
bash scripts/check-ui.sh development
scrolledAwayBeforeReopen = true
reopenSelectsNewest = true
reopenImmediatelyResetsScroll = false
reopenAfterResultsResetsScroll = false
partiallyVisibleFirstCardResetsCompletely = false
status = failed
```

## 定位与根因

优先检查了三条路径：显示时只恢复选中项、列表 reload 布局时序、异步查询覆盖定位。

`show()` 只将 `selectedIndex` 设置为 0，没有明确重置 NSClipView 的横向滚动坐标；查询完成时 `update()` 通过通用 `selectCurrent()` 调用 `scrollToItems(... .nearestHorizontalEdge)`，未在重置场景明确完成布局并将滚动容器移到起点。上述复现同时证明“第一项选中”为真与“滚动复位”为假可以并存。

## 修复

1. 拆开选中项同步和滚动定位。普通选择仍使用原来的临近边缘滚动，不改变浏览行为。
2. 打开前同步第一项选择，完成面板和集合布局，将 NSClipView 的横向坐标设为 0，再显示面板。
3. `resetSelection` 的查询结果更新完成后，同样执行明确的左端定位，覆盖异步加载的情况。
4. 新增“回到最新”按钮，复用同一定位方法，选中当前结果第一项并恢复搜索输入；保留现有筛选，不触发复制或粘贴。
5. 空结果禁用按钮，不添加无界延迟、强制激活其他窗口或延迟抢焦点。

## 回归与验收边界

- 普通与原生全屏分别验证：中部偏移后重开、首项部分可见后重开、6 次带滚动反复重开、打开当下和查询完成后都位于左端。
- 通过真实窗口鼠标按下／抬起事件点击按钮，等待事件处理完成后验证横向坐标、第一项选中和搜索焦点；不直接调用产品的返回方法作为点击证明。
- 验证关键词／类型／时间／收藏保留、空结果禁用、第一卡片完全可见、所有导航路径不执行粘贴。
- 原有卡片动作、重命名、搜索、输入法、全屏与焦点恢复回归一并运行。
- 不读取用户真实剪贴板或历史，不把这些 UI 检查当作实际终端插入或自动升级重启的整链路验证。

## 避免再犯

以后列表复位的验收必须检查滚动容器坐标和首项完整可见，不能只检查选中 ID／索引。异步刷新前后都应有断言，普通浏览定位和“回到起点”应使用各自明确的行为。
