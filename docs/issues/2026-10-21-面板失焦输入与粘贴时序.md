# 面板失焦后的搜索输入与直接粘贴时序

- 日期：2026-10-21。
- 严重程度：P1，高频键盘工作流中断。
- 影响版本：0.1.0。
- 修复版本：0.2.0，修复提交随该版本 Git 历史记录。

## 用户现象

用户点击卡片后，搜索框失焦；继续打字不会搜索。双击希望直接粘贴到唤出前的光标处，但原先经常降级为仅复制；权限提示只给文字，没有打开对应设置。

## 复现与证据

在既有真实 AppKit/WindowServer 隔离测试中，先让 collection 成为 first responder，再向同一窗口发送字符。修复前：

```text
bash scripts/check-ui.sh development
focusLossReproduced = true
typeToSearchFromCards = false
doubleClickChoosesPaste = true
status = failed
```

这证明卡片失焦后的字符路由有缺口；也证明“卡片双击完全没有回调”不是该路径的根因，不能只修改双击监听就声称修复直接粘贴。

## 根因与修复

1. 0.1.0 只在显示面板时聚焦搜索框。卡片获焦后没有窗口级文本输入转交。现在面板在自身是 key window、当前 responder 不是文本编辑器时，对普通文字键先聚焦搜索，再把**同一个事件**交给原生 AppKit 处理，避免首字符丢失或重复插入。
2. 不手工拼接 event.characters 到查询，保留 NSTextInputClient 的输入法组词路径；Command/Control 快捷键、方向键、Return、Esc 分别处理，不截获其他窗口或预览中的文本编辑。
3. 双击在面板窗口命中检测中统一路由，正文、图片、卡片空白区域都按选中项执行粘贴；保留 Option 仅复制、Shift 单次切换格式。
4. 原粘贴代码 `Task.yield()` 后仅检查一次目标焦点。窗口退场与原窗口重新成为 key 是异步过程，可能导致过早降级。现在最多观察 400 ms 的焦点恢复；必须仍是原应用、不能切换原窗口。权限撤回、目标改变或交易取消时不发送按键。
5. 未授权时只复制，然后打开对应系统设置；不会主动替用户开启权限。权限页锚点在本机 Apple 的 SecurityPrivacyExtension 中核实，打开失败退回隐私设置首页。

## 回归

- 普通与原生全屏测试：失焦后直接输入、双击回调、中文组词提交、12 次反复唤出、退出后原窗口与控件焦点恢复通过。
- 测试宿主异步观察窗口恢复，不在 orderOut 同一时间点错误判断 key 状态；最多等 500 ms，最终必须实际恢复。
- 设置模型与纯文本默认/Shift 反转、目标应用/窗口改变时拒绝粘贴，有独立测试。
- 真实终端的授权后按键插入仍需对应应用实测；合成窗口和双击回调不等于跨应用粘贴终端成功。

## 避免再犯

后续窗口和交互修改必须同时运行普通与全屏用例；不能只测初次唤出，也必须测卡片获焦后输入。不要用无限延时或反复激活应用掩盖焦点错误，更不能在目标不确定时把内容粘贴到其他窗口。
